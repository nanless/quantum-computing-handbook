## 二、当前 P2

### P2-1：`verify.mjs` 不能发现“源文件在构建后又改变”

**位置：** `tools/reader/verify.mjs:12,21–23`；对应的 `build.mjs:132` 只记录输出路径和计数。

验证器读取已有的 `reader-build-report.json`，再打开已有 HTML；它没有把当前 Markdown 的哈希或修改状态与构建时状态比较。因此，如果先构建、随后修改正文、最后只运行验证器，旧 HTML 仍可能得到 0 错误。当前这次构建是新鲜的，所以不是现有页面错误，但“验证 0 错误”本身还不能单独证明阅读版对应当前原稿。

**精确修法：**

1. 构建报告逐页记录 `sourceSha256`、`outputSha256`，并记录 `build.mjs` 与 `reader.css` 的哈希；
2. 验证开始时重算当前源和输出哈希，不一致即失败；
3. 或让验证命令总是先调用构建，并清理不再属于当前页面集合的旧 HTML/旧流程图。

### P2-2：公式只比较数量，标题列表已采集却没有参与断言

**位置：** `tools/reader/verify.mjs:43–48`。

当前改进已经检查了未恢复的数学占位符、KaTeX/CSS 是否存在，以及每页 `.katex` 数量是否等于构建报告。但数量相等不能发现两个公式被交换、某个 TeX 原稿被另一个公式替换；`result.headings` 也只是返回，后面没有与构建报告的标题数量或 ID 列表比较。当前内容经本轮独立逐项比较是正确的，缺口在自动回归能力。

**精确修法：**

1. `protectMath` 保存每页按顺序排列的原始 LaTeX 片段，并在构建报告写入 `mathSourceDigest`；
2. 验证器只在 `<article>` 内提取 `annotation[encoding="application/x-tex"]` 的 `textContent`，计算同一摘要并比较；
3. 构建报告保存 `headingIds`，验证器把 `result.headings.map(h => h.id)` 与它逐项比较，而不是只检查重复 ID 和已被链接的锚点。

### P2-3：视觉验证是首屏抽样，打印与局部滚动的真实可用性未被覆盖

**位置：** `tools/reader/verify.mjs:62–65` 与 `reader.css` 的 `@media print` 段。

截图只覆盖 5 个代表页的 1000 px 高首屏，不是整页；390 px 截图前还主动折叠了章节目录。因此截图不能证明：

- 页面下半部的长表、长公式和下一章导航没有视觉问题；
- 表格/公式/流程图虽然位于 `overflow-x:auto` 容器内，但滚动区域实际可操作且内容没有被裁去；
- 页面上提供的“打印本章”在 A4 样式下不会裁掉宽公式或宽表格。

机械检查已覆盖全页水平溢出、图片解码、表格行宽，并新增 SVG 文本 viewBox 检查，所以这是验证边界，不是当前截图中已确认的版面错误。

**精确修法：**

- 代表页增加 `fullPage: true` 截图，另对 `.table-scroll`、`.katex-display`、`.flowchart` 各抽取至少一个 locator 截图；
- 在 390 px 页面上分别保存目录展开与折叠两种状态；
- 用 `page.emulateMedia({media: 'print'})` 加 A4 PDF 或截图冒烟测试，检查 `scrollWidth/clientWidth` 和元素边界；
- 对可横向滚动容器模拟一次 `scrollLeft = scrollWidth`，确认能抵达末端。
