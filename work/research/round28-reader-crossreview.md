## 1. Python 注释不再被误识别为标题

`tools/reader/build.mjs` 当前使用

```js
marked.lexer(text).filter(token => token.type === 'heading')
```

提取 Markdown 的顶层 heading token，不再按原稿中的行首 `#` 扫描。代码围栏内的

```python
# p00=0.463, 95% Wilson=[0.4323, 0.4940]
# [110, 109, 106, 111, 95, 106, 120, 133, 117, 127]
# 0.531 0.603 3.249...
```

因此保持为代码注释。

对当前 `reader/15-practice-research.html` 做独立结构扫描：

- 只有 1 个 H1；
- 正文共有 33 个 H2/H3；
- 手机“本页导航”的 33 个链接与正文 H2/H3 的 ID、顺序完全一致；
- 没有任何以 `#`、`p00`、计数数组或 `0.531` 开头的伪标题。

`verify.mjs` 还会把实际 HTML 标题 ID 序列与构建报告中的 `headingIds` 逐项比较，并同时比较桌面和手机导航与正文 H2/H3 序列。修复不只排除了当前三条注释，也建立了可回归检查。

## 3. 原尺寸图片入口与新纠缠交换图

普通 Markdown 图片统一输出为：

```html
<a class="image-open" href="原图路径">
  <img src="原图路径" ...>
  <span>打开原尺寸图 ↗</span>
</a>
```

当前阅读版共有 7 个这种入口。逐项检查时，链接 `href` 与其中图片 `src` 一致；`verify.mjs` 也会验证这一关系及图片是否成功解码。图像在正文中仍受 `max-width:100%` 约束，不造成页面级横向溢出；读者可点击图片本身或“打开原尺寸图”查看完整 SVG。
